# Project Iron Curtain

## Enterprise Cybersecurity Risk & Security Architecture Program

Project Iron Curtain is an enterprise cybersecurity strategy and architecture project designed to transform a reactive security environment into a proactive, risk-driven security operations model.

The project uses structured risk identification, qualitative risk assessment, risk-to-control mapping, defense-in-depth architecture, centralized security monitoring, governance, incident response, and Secure Software Development Lifecycle monitoring.

---

## Executive Overview

Project Iron Curtain was developed for the Ultra-Enablers INC. case environment as part of postgraduate cybersecurity studies through The University of Texas at Austin.

The project began with an assessment of organizational assets, infrastructure, workforce structure, vulnerabilities, and existing security controls.

Rather than selecting security technologies based only on generic best practices, identified risks were mapped to preventive, detective, and corrective controls based on the organization's specific exposure.

## Core Security Strategy

Risk Identification -> Risk Assessment -> Risk Prioritization -> Control Mapping -> Defense-in-Depth -> Centralized Monitoring -> Incident Response -> Continuous Improvement

---

## Key Risks Identified

The assessment identified risks affecting endpoints, email, cloud storage, network infrastructure, proprietary software, mobile devices, servers, CRM systems, development documentation, and financial systems.

Critical risks included:

- Malware infection
- Phishing attacks
- Intellectual property theft
- Ransomware

Additional high risks included:

- Cloud data breach
- Unauthorized network access
- CRM data leakage
- Insider threat
- Fraudulent transactions

---

## Defense-in-Depth Architecture

Project Iron Curtain combines multiple security layers:

### Preventive Controls

- Endpoint Detection & Response (EDR)
- Secure Email Gateway
- Next Generation Firewall
- Multi-Factor Authentication
- Data Loss Prevention

### Detective Controls

- Security Information and Event Management (SIEM)
- Centralized log collection
- Security correlation
- SOC monitoring
- Threat intelligence enrichment

### Corrective Controls

- Incident response procedures
- Technical containment
- Forensic investigation
- Recovery activities
- Incident documentation

---

## Risk-to-Control Strategy

| Risk | Primary Control |
|---|---|
| Malware infection | Endpoint Detection & Response |
| Phishing attacks | Secure Email Gateway |
| Unauthorized network access | Next Generation Firewall |
| Credential theft | Multi-Factor Authentication |
| Data exfiltration | Data Loss Prevention |
| Lack of centralized monitoring | SIEM |

---

## Security Operations Model

The proposed monitoring architecture centralizes telemetry from:

- Endpoints
- Servers
- Firewalls
- Authentication systems
- Email security systems
- Cloud platforms

A SIEM provides centralized collection and correlation.

The proposed SOC capability reviews alerts, validates suspicious activity, escalates confirmed incidents, and maintains incident documentation.

Because of the organization's size, the capstone identifies a managed SOC provider as a possible initial approach to 24/7 monitoring.

---

## Governance

Cybersecurity responsibilities extend beyond IT.

Project Iron Curtain defines cross-functional responsibilities involving:

- Executive leadership
- Chief Technology Officer
- IT administrators
- Security operations
- Human Resources
- Legal and Privacy

This establishes cybersecurity as an organizational risk-management program rather than an isolated IT function.

---

## Secure SDLC Monitoring

Because the organization develops proprietary software, security monitoring also extends into development environments.

Monitoring areas include:

- Source-code repositories
- Developer authentication activity
- Unauthorized code downloads
- Abnormal repository access

This protects both infrastructure and intellectual property.
